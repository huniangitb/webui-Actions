# Plan: Fix injector conf ON/OFF state and app rule parsing

## Problem
In `apps.ts:149-153`, the `isEnabled` logic requires a rule FILE to exist for ON to take effect:
```javascript
const isEnabled = ruleFilesMap.get(`${exactKey}_enabled`)
  ? true
  : ruleFilesMap.get(`${exactKey}_disabled`)
    ? false
    : stateVal === "ON" && hasRulesFile;  // ← hasRulesFile is false when rules are only in injector.conf
```

When an app has `[pkg] ON` in injector.conf with inline rules (e.g., `REDIRECT /test /Download`) but no separate rule file at `/App-rules/pkg.conf`, `hasRulesFile` is `false`, so `isEnabled` evaluates to `false`. This causes:
1. ON apps appear as "not configured"
2. Inline rules in injector.conf are not visible in the app config UI

Additionally, `isConfiguredAny` (line 154) only becomes true when a rule file exists OR state is OFF, so ON-only apps don't show as configured in badges.

## Fix

### File: `src/apps.ts`

**Change 1** — Fix `isEnabled` logic (line 149-153):
When there's no rule file but the injector state is ON and inline rules exist in `injectorRulesMap`, treat as enabled.

```typescript
const isEnabled = ruleFilesMap.get(`${exactKey}_enabled`)
  ? true
  : ruleFilesMap.get(`${exactKey}_disabled`)
    ? false
    : stateVal === "ON" && (hasRulesFile || (state.injectorRulesMap.get(exactKey)?.length ?? 0) > 0);
```

**Change 2** — Fix `isConfiguredAny` logic (line 154):
Also consider apps that have inline rules in injector.conf as configured.

```typescript
if (hasRulesFile || stateVal === "OFF" || (state.injectorRulesMap.get(exactKey)?.length ?? 0) > 0) isConfiguredAny = true;
```
